# 📚 توثيق QVM Platform — دليل القراءة

> **قاعدة المشروع:** كل خطوة تُوثَّق 100%. أي مطوّر جديد يقدر يكمّل الشغل من هذه الوثائق وحدها،
> بدون ما يسأل حد. أي شغل غير موثَّق = شغل غير مكتمل.

## من أين تبدأ (للمطوّر الجديد)

اقرأ بهذا الترتيب:

1. **[ONBOARDING.md](ONBOARDING.md)** — تهيئة جهازك وتشغيل المشروع خلال دقائق.
2. **[ARCHITECTURE.md](ARCHITECTURE.md)** — المرجع المعماري الكامل: الستاك، الـ multi-tenancy، الـ sandbox، البيئات، خارطة الطريق.
3. **[CONVENTIONS.md](CONVENTIONS.md)** — قواعد الكود والداتابيز والـ git الملزمة للجميع.
4. **[decisions/](decisions/)** — سجل القرارات المعمارية (ADRs): *ليش* اخترنا كل حاجة، بالبدائل المرفوضة وأسبابها.
5. **[phases/](phases/)** — سجل تنفيذ كل مرحلة: ما الذي عُمل بالضبط، الأوامر، الملفات، والحالة.

## خريطة الوثائق

| الوثيقة | محتواها | متى تُحدَّث |
|---|---|---|
| `ONBOARDING.md` | تهيئة بيئة التطوير خطوة بخطوة | عند تغيّر خطوات التشغيل |
| `ARCHITECTURE.md` | البنية الكاملة والقرارات السارية | عند أي تغيير معماري |
| `CONVENTIONS.md` | قواعد الكود/DB/git الملزمة | عند إضافة قاعدة جديدة |
| `decisions/NNNN-*.md` | قرار واحد لكل ملف (ADR) | **يُضاف ولا يُعدَّل** — القرار الملغي يُشار له بـ superseded |
| `phases/phase-N-*.md` | سجل تنفيذ المرحلة N | أثناء وبنهاية كل مرحلة |

## قواعد التوثيق الإلزامية

1. **كل قرار معماري → ADR** في `decisions/` قبل أو مع التنفيذ (ليش، البدائل، السبب).
2. **كل مرحلة → phase log** يُحدَّث أولاً بأول: الأوامر التي نُفّذت، الملفات التي أُنشئت، المشاكل وحلولها.
3. **كل موديول جديد → README** داخل مجلده يشرح مسؤوليته وحدوده وواجهته.
4. **كل جدول/عمود غير بديهي → تعليق** في ملف الـ schema نفسه.
5. **الـ commit messages وصفية** وتشير للمرحلة/الـ ADR المتعلق.
6. التوثيق **جزء من تعريف "خلصت"** — ما يتقفلش شغل بدون تحديث وثائقه.
