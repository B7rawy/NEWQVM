# 📏 Conventions — القواعد الملزمة

> هذه القواعد **ملزمة** لأي كود يدخل الريبو. وُضعت خصيصاً لمنع تكرار مشاكل النظام القديم
> (المذكورة في [ARCHITECTURE.md §1](ARCHITECTURE.md)). أي PR يكسر قاعدة منها يُرفض.

## المبدآن الحاكمان (فوق كل القواعد)

**أ. مصدر واحد — صفر ازدواج.** قاعدة بيانات **واحدة**، ريبو **واحد**، تطبيق **واحد** لكل طبقة،
مصدر **واحد** لكل منطق. ممنوع منعاً باتاً: أكثر من قاعدة بيانات للنظام، أكثر من ريبو، نسخ متوازية
من نفس الشيء (v2/v3/.bak)، schema مكرر، دالة/منطق مكرر في مكانين. **هذا عكس فوضى القديم بالضبط**
(3 قواعد `MIGRATIONS_FAILED`، ازدواج `public`/`qvm_new_apps`، 3 أجيال داشبورد). أي تكرار = خطأ يُرفض.

**ب. يشتغل فعلاً، لا نظرياً.** لا يُعتبر أي شيء "خلص" إلا بعد تشغيله والتحقق منه فعلياً
(اختبار/تنفيذ حقيقي، ليس مجرد كود يُفترض أنه يعمل). الإطلاق مشروط بأن يكون النظام مُختبَراً
end-to-end وكل feature مُثبَت عملها — انظر [phases/phase-6](phases/) (تصليب + اختبار scale + اعتمادية).

## قاعدة البيانات

1. **كل جدول أساسي يحمل `tenant_id`** (FK → `tenants`) + composite index يبدأ بـ `(tenant_id, …)`.
2. **RLS مفعّل على كل جدول** مع policy العزل — بدون استثناء، ومن أول ميجريشن للجدول.
   - الجداول tenant-scoped: `enable` + **`force`** + policy `tenant_id = current_tenant_id() OR app_is_internal()`.
   - **التطبيق يتّصل بدور `qvm_app` (غير superuser)** المخضِع للـ RLS — **ممنوع** التشغيل بدور الـ owner/superuser
     (يتخطّى الـ RLS ويُبطِل العزل). الميجريشن والـ seed فقط يستخدمان دور الـ owner. كل request يضبط
     `SET LOCAL app.tenant_id / app.user_id / app.is_internal`.
3. **كل FK له index يغطّيه.** (القديم: 123 FK بدون index.)
4. **أرقام متسلسلة = PostgreSQL sequence** — ممنوع نمط `MAX()+1`. (القديم: قنبلة توليد أرقام الطلبات.)
5. **schema واحد** (`app` أو `public` الجديد النظيف) — ممنوع ازدواج الدوال/الجداول بين schemas.
6. الأسماء `snake_case`، إنجليزية، مفردة الوضوح — ممنوع جداول باسم فيه "duplicate" أو "test" أو "old".
7. الميجريشنز عبر drizzle-kit فقط، **اتجاه واحد** (لا تعديل ميجريشن سابق)، وتُطبَّق local → staging → prod.
8. أي عمود غير بديهي → تعليق في ملف الـ schema.

## الباك إند (NestJS)

1. **موديول لكل مجال** (`rfq`, `orders`, `vendors`, …) — ممنوع god-module أو god-service. حد إرشادي: ملف > 400 سطر = راجع تقسيمه.
2. **كل endpoint خلف guard صريح** (auth + role + tenant) — لا يوجد endpoint "مفتوح افتراضياً".
3. **الآثار الجانبية (إيميل/واتساب/دفع/webhooks) عبر موديول `notifications` فقط**، وكلها تمرّ على sandbox guard (`environment = 'sandbox'` — ADR-0012). ممنوع استدعاء provider خارجي مباشرة من أي service آخر.
4. **DTOs بـ zod** على الحدود + أنواع Drizzle من السكيما — **ممنوع `any`** في طبقة الداتا. (القديم: 788 `any`.)
5. **الأخطاء لا تُبلَع**: ممنوع `catch {}` فارغ. إمّا معالجة حقيقية أو إعادة رمي مع سياق. (القديم: 63 catch فارغ.)
6. لا `console.log` — استخدم logger الـ NestJS.

## الفرونت إند (React)

1. **lazy route لكل صفحة** — ممنوع static import لكل الصفحات في ملف واحد. (القديم: chunk واحد 3MB.)
2. **جيل واحد لكل شاشة** — ممنوع ملفات `v2`/`v3`/`.bak` في الريبو نهائياً.
3. **مصدر واحد** للتنسيقات المشتركة: عملة/تاريخ/ألوان حالات في `packages/shared` أو `web/src/lib` — ممنوع إعادة تعريف محلية.
4. i18n موديول top-level مشترك — القواميس بجانب بعضها، ليست مدفونة داخل صفحة.
5. طبقة داتا واحدة (API client) — المكوّنات لا تنادي HTTP مباشرة.

## Git

1. **Conventional commits**: `feat:` / `fix:` / `chore:` / `docs:` / `refactor:` + إشارة للمرحلة أو الـ ADR عند اللزوم.
2. الشغل على branches، و`main` دائماً يبني وينجح typecheck.
3. **ممنوع أسرار في git** — `.env` خارج الريبو دائماً، و`.env.example` هو القالب. (القديم: PAT مدفون في الـ remote.)
