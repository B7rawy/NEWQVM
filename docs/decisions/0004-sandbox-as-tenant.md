# ADR-0004: بيئة تيست الإدارة = sandbox tenant + عزل إلزامي للآثار الجانبية

> **⚠️ مُلغى — استُبدل بـ [ADR-0012](0012-environment-as-row-boundary.md) (2026-07-25).**
> `tenants.is_sandbox` حُذف. البيئة صارت عموداً على الصف يفرضه RLS، لا workspace منفصلاً.
> السبب: صفوف الـ "Sandbox Workspace" كانت تُكتب بـ `environment = 'live'` فظهرت في بوابة
> مورّد حقيقي — أي أن هذا التصميم **بدا** عزلاً ولم يكن. تبقى قاعدة عزل الآثار الجانبية أدناه
> سارية، لكنها تفحص الآن `environment` بدل `tenant.is_sandbox`.

**الحالة:** ~~مقبول — 2026-07-22~~ → مُلغى 2026-07-25

## القرار
- بيئة تجربة الإدارة = **tenant عادي بعلامة `is_sandbox = true`** (وليس بيئة/سيرفر منفصل).
- نفس الكود والسلوك 100%، معزول بالـ RLS، له subdomain خاص (مثل `sandbox.<root>`).
- **seed** ببيانات وهمية واقعية + **reset بضغطة** (مسح صفوف الـ tenant + إعادة seed).
- يجوز أكثر من sandbox (لكل مدير/سيناريو).

## القاعدة الحرجة: عزل الآثار الجانبية
كل side-effect (إيميل، واتساب، دفع، webhooks، sheets، PDFs للموردين) يمرّ عبر
موديول `notifications`/providers موحّد **يفحص `tenant.is_sandbox`**:
- sandbox → console/mailtrap/no-op/وضع sandbox للبوابة.
- ممنوع منعاً باتاً وصول أي رسالة/فلوس حقيقية من sandbox لأي طرف خارجي.
- ممنوع استدعاء provider خارجي من خارج هذه الطبقة (يفرضها CONVENTIONS §Backend-3).

## البدائل المرفوضة
- **Toggle على بيانات الشركة الحقيقية:** خطر تلويث/حذف داتا حقيقية.
- **بيئة staging منفصلة للإدارة:** تنجرف عن الإنتاج (drift) وتضاعف التشغيل؛
  الـ staging يبقى للمطوّرين فقط (اختبار كود وميجريشنز)، وهو شيء مختلف تماماً.
