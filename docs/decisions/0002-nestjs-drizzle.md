# ADR-0002: NestJS للباك إند + Drizzle للـ ORM والميجريشنز

**الحالة:** مقبول — 2026-07-22

## القرار
الباك إند NestJS (TypeScript) بموديول لكل مجال. طبقة الداتا والميجريشنز عبر Drizzle.

## السياق
أكبر أمراض القديم: منطق بيزنس مدفون في ~300 دالة SQL مكررة بين schemas بلا اختبارات،
god-modules، و788 `any` لأن ردود الـ RPC غير مُتايَبة.

## لماذا NestJS
- معمارية مفروضة (modules/providers/guards) تمنع هيكلياً تكرار القديم.
- guards صريحة لكل endpoint = نموذج تفويض واضح بدل SECURITY DEFINER مفتوح.

## لماذا Drizzle
- الأنواع تتولّد من السكيما → يستحيل `any` على حدود الداتا.
- ميجريشنز SQL شفافة (drizzle-kit) بمصدر واحد في الريبو — بديل فوضى الـ 3 قواعد `MIGRATIONS_FAILED`.
- خفيف وقريب من SQL (مهم لأننا ننقل منطقاً من دوال SQL موجودة).

## البدائل المرفوضة
- **Express/Fastify خام:** لا يفرض تنظيماً — خطر إعادة إنتاج العك القديم.
- **Prisma:** مقبول، لكن Drizzle أقرب لـ SQL وأخف، وأنسب لترجمة دوال القديم.
- **إبقاء المنطق في دوال SQL:** يكرر مشكلة القديم (منطق غير مُختبَر وغير مرئي في الريبو).
