# ADR-0010: قاعدة multi-tenant واحدة (رفض القاعدة-المنفصلة-لكل-شركة) + نموذج الهوية والتبديل بين الـ workspaces

**الحالة:** مقبول — 2026-07-22 (قرار صاحب المشروع صراحةً)

## القرار

### 1. قاعدة بيانات واحدة multi-tenant — نهائي
كل الشركات في **قاعدة Postgres واحدة** بـ `tenant_id` + RLS + ساب-دومين لكل workspace.
**تُرفض صراحةً** رؤية QNEW-56 (قاعدة Supabase منفصلة فيزيائياً لكل شركة + hub-and-spoke عبر Edge Functions).

**السبب:** تصميمنا يوصّل نفس هدف QNEW-56 (عزل كامل بين الشركات + مورّد مشترك عبرها) لكن بـ
**query أصلي** بدل فيدرالية API معقّدة، ويحل بقية الرودماب (تمويل على مستوى الشركة، إعدادات شحن
per-tenant، تقارير موحّدة) أنظف. مفاهيم "Vendor Hub" (QNEW-56) **تُطوى كجداول داخل قاعدتنا**:
`vendors` عالمي (tax_number unique)، `tenant_vendors` = رابط الشركة↔المورّد بحالة pending/accepted،
`vendor_users` متعدد الدخول — كلها موجودة/مخطَّطة (ADR-0008) بلا حاجة لقواعد منفصلة.

### 2. نموذج الهوية — ثلاث طبقات وصول
كشفه متطلب "التبديل بين الـ workspaces": "الداخلي" لا يُشتق من عضوية tenant واحد.

| الطبقة | الجدول | الوصول |
|---|---|---|
| موظفو المنصّة (Qparts) | **`platform_members`** (جديد): user_id + `platform_role` | يرون **كل** الـ workspaces (`app.is_internal = true`) |
| مستخدمو الورش | `tenant_memberships`: user_id + tenant_id + role (+ workshop_branch) | الـ workspaces اللي لهم فيها عضوية |
| مستخدمو الموردين | `vendor_users` → المورّد → `tenant_vendors` | الـ workspaces المرتبط بها المورّد |

`platform_role` enum يشمل أدوار Qparts الداخلية + `finance_manager` و`pricing_supervisor`
(يعالج تعارض الأدوار الذي رصده QNEW-48-A بين القائمة والكود).

### 3. التبديل بين الـ workspaces (يُصمَّم الآن، تُبنى الواجهة في وقتها)
- **التوكن (JWT) عام** (sub = user_id) ولا يحمل tenant — يظل صالحاً عبر كل الـ workspaces.
- الـ workspace النشط يُحسم **لكل request** من الساب-دومين (أو رأس `X-Tenant` للتطوير).
- **`GET /api/workspaces`** يرجّع كل الـ workspaces التي يصلها المستخدم (من الطبقات الثلاث) —
  هو أساس السويتشر في الواجهة.
- **التبديل = التنقّل لساب-دومين الـ workspace الآخر**؛ الـ guard يعيد حساب tenant+role لكل request.
- الوصول لـ workspace بلا عضوية (ولا صفة platform) = **403**.

## النتائج
- إلغاء أي أثر لفكرة القواعد المنفصلة في التصميم والوثائق.
- `AuthGuard` يحسب `is_internal` من `platform_members` (لا من دور tenant)، ويمنع الوصول لغير الأعضاء.
- **أثر على الواجهة (لاحقاً):** سويتشر workspaces في الهيدر، وإعادة توجيه للساب-دومين عند التبديل،
  وحالة "لا صلاحية لهذا الـ workspace". يُبنى عند مرحلة الفرونت، والأساس الخلفي جاهز من الآن.
